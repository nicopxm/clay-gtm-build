Clay data: measured from Steps 1–3 execution logs and the Clay Usage panel (day2_debrief.md).
n8n data: measured for match rate, fields returned, and API-call counts (outputs/step4_benchmark_capture.csv); cost is a **confirmed $0.00**, not an estimate needing a label — see note below.

## 3-sentence verdict

Clay wins on time-to-value for a short, low-volume sprint. Cost-ordered waterfalls, pre-run condition checks, and one-click contact/email/CRM actions took an 8-account enrichment from job posting to pushed HubSpot contact in a few days at modest credit cost. n8n wins on marginal cost and control — the equivalent website/tech-stack/news enrichment ran at a confirmed $0.00 per account with fully custom retry and status semantics — but only for a narrower slice of the pipeline than Clay covered end-to-end, and this benchmark showed real setup friction Clay doesn't have: no webhook access, a single-lead execution model that blocks ad-hoc batch testing, and a news step that reports false-positive collisions as clean successes. For a fast, deadline-bound GTM sprint like this one, Clay is the right call; for a mature, high-volume pipeline where per-record marginal cost matters more than setup speed, n8n is worth the integration effort — but only once #23 orchestration (REALITY §1) ships, since today's one-lead-at-a-time model doesn't scale to batch work without manual caution.
